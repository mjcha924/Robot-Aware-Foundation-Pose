01 · 우리가 학습하려는 것

FoundationPose가 이미 이해하는 시각 정보에 로봇의 형상과 움직임을 보태, 물체가 가려지는 조작 과정에서 물체의 6D pose를 더 잘 추적할 수 있는지 시험한다.

6D pose는 위치 3자유도와 회전 3자유도다. 로봇의 행동을 생성하는 정책을 학습하는 프로젝트가 아니다. 현재 RGB-D와 pose hypothesis를 보고 물체 자세를 수정하는 refiner를 학습한다. 물체 CAD를 아는 model-based 조건이다.

이 문서는 현재 코드가 하는 일과 아직 GPU에서 확인해야 할 일을 구분한다. 로컬 테스트 58개 통과, CUDA 관련 1개 skip. 실제 OMY 데이터의 학습 성공·정확도 향상·5080 호환성은 아직 측정 전이다.

처음에는 02~08을 읽고, 실행할 때는 10을 따라간다. 결과를 해석할 때는 11~14로 돌아온다. 페이지의 수치 예시는 실제 학습 결과가 아니라 계산 예시로 표시했다.

02 · 먼저 익힐 학습 용어

용어우리 코드에서의 의미
Sample한 프레임의 관측 + 시작 pose + robot points + 정답 pose 묶음. 한 프레임에 다른 시작 pose를 만들면 다른 sample이 될 수 있다.
Parameter / weight학습으로 바뀌는 숫자. Point encoder의 Linear 가중치, attention 가중치 등이 해당한다. 관절값 q는 입력 데이터이지 학습 파라미터가 아니다.
Batch한 번의 업데이트에 사용하는 sample 묶음. batch 4면 보통 4개 sample의 평균 오차로 업데이트한다.
Step / iteration학습에서는 대개 optimizer 업데이트 한 번. 추론 refinement iteration은 pose 수정 반복 횟수로, 학습 step과 다르다.
Epochtrain sample을 한 차례 모두 사용한 단위. 20 epochs는 같은 데이터에서 20번 학습한다는 뜻이다.
Loss모델이 얼마나 틀렸는지 나타내는 미분 가능한 숫자. 여기서는 물체 CAD 표면점 위치의 평균 오차다.
Gradient / backward각 weight를 어느 방향으로 바꾸면 loss가 줄어드는지 연쇄 미분으로 계산하는 과정.
Learning rate업데이트 크기를 조절하는 값. 너무 크면 발산할 수 있고 너무 작으면 변화가 느릴 수 있다.
Optimizergradient로 실제 weight를 업데이트하는 규칙. 이 코드에서는 AdamW를 사용한다.
Frozenweight를 업데이트하지 않는 상태. 해당 연산의 입력으로 gradient를 전달하는 것과는 별개다.
Checkpoint학습 중 weight와 optimizer 상태 등을 저장한 파일. pretrained weights는 출발점, 우리의 best.pt는 학습 결과다.
Train / validation / testtrain은 업데이트용, validation은 선택·조정용, test는 최종 독립 평가용. 현재 9개는 validation이며 독립 test가 아니다.

03 · 데이터는 무엇을 가르치는가

유형관측 상황배워야 할 관계
A · 비접촉 가림물체는 놓여 있고 로봇이 앞을 지나간다.로봇이 움직였다고 물체까지 움직였다고 추정하면 안 된다.
B · Grasp / carry실제 grasp 후 lift, hold, 이동과 회전.로봇 motion이 object motion에 유용할 수 있다.
C · Place / release잡힌 물체를 놓고 로봇이 물러난다.release 이후에는 로봇 motion을 계속 따라가면 안 된다.

물체는 gelatin box, large marker, banana 세 개다. 총 45개 시퀀스·11,999프레임(30 Hz). Train 36개·9,617프레임, validation 9개·2,382프레임이다. 5프레임마다 하나씩 고르면 최대 train 1,926 / validation 478 sample이다. 11,999프레임은 11,999개의 독립 장면을 뜻하지 않는다.

Physical parent는 원래 같은 물리 rollout에서 나온 clip의 묶음이다. 같은 parent의 B/C가 train과 validation에 나뉘면 거의 같은 장면을 미리 본 셈이 된다. 원래 manifest split을 유지하고 parent 중복을 검사한다.

B는 batch size, L은 visual token 수다. L은 crop 크기와 encoder 출력에 따라 정해지므로 고정 숫자로 가정하지 않는다. 실제 기본 robot encoder는 32개 local token을 만든다. 예전 설계 토론의 64/128 token 후보와 현재 구현을 구분하자.

왜 여러 local token인가? 각 시각 위치가 다른 로봇 영역을 참조할 수 있게 하려는 것이다. 로봇 전체를 하나의 벡터로 줄이면 일반적인 cross-attention의 Key가 하나여서 선택의 여지가 없어진다. 다만 cross-attention을 넣었다는 사실만으로 성능이 좋아지는 것은 아니다.

왜 residual인가? 원래 시각 특징을 유지하면서 필요한 보정만 더한다. α는 0.01에서 시작하는 학습 가능한 scale이다. 학습을 거치며 크기와 부호가 바뀔 수 있고, 현재 코드에 범위 제한은 없다. α=0 bypass와 일반 forward는 구분된다.

05 · Robot state가 신경망 입력이 되는 과정

관절각 q를 그 자체로 단순 연결하지 않는다. q → FK → 로봇 표면점으로 바꿔 영상과 비교할 수 있는 기하 표현을 만든다. FK는 joint inventory에 정의된 관절축·부모/자식 관계와 관측 관절각으로 link pose를 계산한다.

  1. 각 link mesh에서 canonical point를 고정 샘플링한다. 전체 로봇 512점이다.
  2. 같은 표면점을 현재와 이전 관절 상태로 각각 변환한다. 매 프레임 다른 점을 뽑으면 속도 계산에 샘플링 노이즈가 섞인다.
  3. 두 시점의 점을 동일한 현재 카메라 좌표계로 표현한다.
  4. (현재점 − 이전점) / Δt로 속도를 계산한다. 새 reader의 motion_camera_m 자체는 변위이므로 바로 속도로 사용하면 안 된다.
  5. 시작 pose의 역변환을 적용하고 물체 diameter로 정규화한다. 법선은 회전만 적용한다.
  6. 물체 CAD 256점을 더해 총 768개의 11차원 점을 만든다.

Geometry 모드는 속도와 validity 채널을 0으로 만든다. Motion 모드는 이를 유지한다. 물체 CAD는 이미 알고 있는 형상이고, GT 현재 pose로 배치된 점을 몰래 넣는 것이 아니다.

좌표계에서 자주 생기는 오류

T_A_B는 B 좌표를 A로 바꾼다. depth PNG는 mm지만 모델은 m를 사용한다. object root, raw mesh, centered mesh frame을 혼동하지 않는다. 새 adapter는 모델의 raw mesh pose를 reader의 object-root pose로 변환한다. frame 0의 속도도 실제 previous_robot_state로 계산한다.

06 · 정답과 시작 pose는 어떻게 만드는가

학습 샘플은 “물체를 처음 발견하는 문제”보다 주어진 pose를 고치는 문제다. Registration은 별도의 초기화 단계이고, 이 코드의 학습 대상은 refinement다.

모드시작 pose해석
perturbed현재 GT pose에 translation/rotation 노이즈첫 geometry 학습과 구현 검증
previous직전 GT pose를 현재 camera로 옮긴 뒤 노이즈motion과 다음 pose update 관계를 배우는 temporal supervision
평가 rollout직전 모델 prediction오차가 누적되는 실제 tracking 조건

기본 perturbation은 translation 각 축 표준편차 0.01m, rotation axis-angle 각 성분 표준편차 10°다. “언제나 정확히 10mm·10° 틀린다”는 뜻이 아니다. 표준편차가 있는 확률 분포에서 뽑는다.

Previous 모드는 선택 프레임이 5프레임 간격이어도 실제 직전 프레임 i−1의 pose를 사용한다. frame 0에는 이전 object GT가 없으므로 제외한다. 이것은 teacher forcing이며, 아직 모델 자신의 이전 오답을 이용하는 on-policy 학습은 아니다.

GT를 학습 target이나 학습용 hypothesis 생성에 쓰는 것은 supervised learning의 일부다. 추론에서 매 프레임 GT를 넣거나, validation 정답으로 tracking을 계속 초기화하면 다른 평가가 된다.

07 · 왜 먼저 cache를 만드는가

Rendering과 visual encoder는 GPU 비용이 들지만, 이번에는 visual encoder를 고정한다. 같은 sample을 20번 학습하면서 같은 렌더링을 20번 할 필요가 없으므로 visual token을 한 번 저장한다.

prepare_robot_refiner.py
  sequence 읽기 → hypothesis 만들기
  → RenderBridge.pair(): 실제 RGB-D와 렌더 crop 구성
  → model.encode_visual(): frozen feature 추출
  → point features + target + CAD와 함께 sample .pt 저장
  → heads.pt, manifest.json 저장

train_robot_refiner.py
  cache 읽기 → robot encoder → fusion → pose heads
  → loss → backward → optimizer.step()

Cache에는 visual, points, hypothesis, target, CAD, diameter, symmetries가 들어 있다. Manifest는 weight hash, upstream commit, config, sequence hash와 parent group을 기록한다. 서로 다른 원본 weights나 config의 cache를 섞으면 거부한다.

Hypothesis를 바꾸면 렌더 crop과 visual token도 바뀐다. 그래서 temporal cache는 별도로 만든다. 이 방식은 fixed augmentation이다. 더 많은 epoch를 돌려도 새로운 random perturbation이 자동으로 생성되지는 않는다.

08 · 학습 step 안에서는 무슨 일이 일어나는가

for batch in train_loader:
    optimizer.zero_grad(set_to_none=True)
    output = model.forward_tokens(batch['visual'], batch['points'])
    predicted_pose = decode_pose(output, batch['hypothesis'], ...)
    loss = pose_loss(predicted_pose, batch['target'], batch['cad'], ...)
    loss.backward()
    clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()

이 코드는 개념을 보여주기 위해 인자를 줄인 것이다. 실제 구현은 trainer.py의 batch_loss()와 run()에 있다. AdamW는 gradient의 누적 통계도 가지고 있어서 resume에 optimizer state가 필요하다. Gradient clipping은 전체 gradient norm이 1을 넘으면 크기를 제한한다.

각 epoch가 끝나면 model.eval()과 no_grad()로 validation을 수행한다. Validation에서는 weight를 업데이트하지 않는다. 이 결과가 가장 낮으면 best.pt를 갱신하고, 마지막 상태는 last.pt에 저장한다.

Frozen heads인데 어떻게 encoder가 학습되는가?

heads weight의 requires_grad=False는 weight를 바꾸지 않겠다는 뜻이다. heads가 입력 특징에 수행하는 연산은 여전히 미분 가능하다. loss의 gradient는 heads를 통과해 fusion과 robot encoder로 전달된다. 따라서 heads 전체를 no_grad로 감싸면 이 학습 경로를 끊을 수 있다. Visual encoder는 입력 영상 자체를 학습할 필요가 없으므로 cache 생성에서 no_grad를 써도 된다.

09 · Loss와 hyperparameter를 읽는 법

예측 pose로 변환한 CAD점과 GT pose로 변환한 같은 CAD점 사이의 거리를 평균한다.

L = meanᵢ ‖ T̂ pᵢ − Tᴳᵀ pᵢ ‖₂

정확한 대칭 변환이 제공되면 허용된 변환 중 최소 오차를 택한다. 없으면 identity만 사용한다. 원통처럼 보인다는 이유로 texture·형상의 대칭을 임의로 선언하지 않는다. 이 loss는 무조건 최근접점을 찾는 ADD-S와 같은 정의가 아니다.

예를 들어 surface error 0.004는 평균 4mm다. 이것은 translation error 4mm와 같지 않다. 회전이 틀려도 표면점 위치가 어긋나기 때문이다.

설정기본값바꾸면 무엇이 달라지는가
batch-size4VRAM과 update당 sample 수. OOM이면 2/1로 낮추되 비교 실험 조건을 기록한다.
epochs20학습 반복 횟수. 많다고 항상 validation이 좋아지지 않는다.
lr1e-4새 encoder/fusion 업데이트 크기.
head-lr1e-5pretrained heads를 더 작게 조정한다.
warmup-epochsTiny 20, pilot 0해당 epoch 동안 heads 고정. visual-only에서 양수는 학습 대상이 없어 오류로 막는다.
stride5cache에 선택할 프레임 간격. 로봇 속도 계산 Δt와 다르다.
seed학습 42초기화·shuffle 재현에 도움. 다른 GPU 간 완전 동일 결과를 보장하지 않는다.

계산량 직접 계산하기

고정 geometry cache의 train 1,926 / validation 478개를 기준으로 한 산술 계산이다. 시간·성능 예측은 아니다.

10 · 5080에서 순서대로 실행하기

대상은 Linux와 NVIDIA GPU다. 아래 명령은 5080에서 원본 FoundationPose가 작동하는 Python 또는 컨테이너 환경 안에서 실행한다. Isaac Sim이 실행된다는 것만으로는 이 조건을 만족하지 않는다. CUDA 11.8/PyTorch 2.0의 옛 3070 환경을 5080에 그대로 복사하지 않는다. Blackwell 지원 PyTorch/CUDA 및 native extension 조합을 먼저 검증한다. PyTorch Blackwell 지원 안내.

현재 이 브랜치의 실제 5080 검증은 아직 전이다. 환경이 없다면 upstream 설치 안내와 docs/BASELINE.md의 의존성 목록을 참고하되, 그 문서의 옛 버전 조합은 5080용 설치 처방이 아니다. 새 환경이 실제 rendering gate를 통과할 때까지 학습을 진행하지 않는다.

원래 FoundationPose가 동작하는 환경을 활성화한 뒤 실행한다. 컨테이너라면 저장소와 dataset 경로를 컨테이너 안에서 접근할 수 있게 mount해야 한다. 호스트의 경로를 컨테이너 경로와 혼동하지 않는다.

nvidia-smi
python -c "import torch; print('torch',torch.__version__,'cuda',torch.version.cuda); assert torch.cuda.is_available(); print(torch.cuda.get_device_name(0)); x=torch.randn(64,64,device='cuda'); print((x@x).mean().item())"
python -m pip install -r requirements-training.txt

이 requirements는 추가 reader/test 의존성이다. torch나 전체 FoundationPose 환경을 설치하지 않는다. pretrained weights는 별도 준비하며 third_party/FoundationPose/weights/의 upstream 지정 구조를 따른다. 코드 저장소에는 weights가 없다.

3 데이터와 출력 경로 지정

아래 DATASET은 캡처 머신에 기록된 경로다. 다른 컴퓨터로 옮겼거나 컨테이너 안에서 실행하면 반드시 수정한다. 최종 dataset 디렉터리와 공식 checksum 파일을 함께 가져와야 한다. 데이터 디렉터리 이름은 checksum의 dataset/... 상대 경로와 맞춘다.

export OMY_DATASET=/home/a09/mj-projects/omy-tracking-dataset/outputs/omy_pilot/dataset
export OMY_CHECKSUMS=/home/a09/mj-projects/omy-tracking-dataset/outputs/omy_pilot/accepted_checksums.sha256
export OMY_WORK="$PWD/outputs/omy_training_001"
test -d "$OMY_DATASET"
test -f "$OMY_CHECKSUMS"
python scripts/check_omy_training_readiness.py --dataset "$OMY_DATASET"

점검 도구의 exit 0은 학습 준비 완료를 뜻하지 않는다. 뒤의 CUDA/실제 rendering gate가 필요하다. OMY_WORK는 새 경로로 정하며 기존 실행 결과를 덮어쓰지 않는다.

4 실행 계획 확인

python scripts/run_omy_training.py --dataset "$OMY_DATASET" \
  --work "$OMY_WORK" --stage smoke

--execute가 없으므로 어떤 학습이나 GPU 작업도 하지 않는다.

5 첫 GPU 검증

전체 공식 checksum 검증 → 원본 출력 일치와 gradient 검사 → A/B/C 각 2개 실제 sample cache 생성 순서다. 마지막까지 성공하면 총 6개 sample이 만들어진다. 자동 검사는 이미지 overlay를 사람이 검토한 것을 대신하지 않는다.

python scripts/run_omy_training.py --dataset "$OMY_DATASET" \
  --work "$OMY_WORK" --stage smoke --checksums "$OMY_CHECKSUMS" --execute

오류가 나면 여기서 멈추고 마지막 traceback을 확인한다. 원본 weights, native extension, CUDA 오류를 무시하고 학습 단계로 넘어가지 않는다.

6 학습 cache 준비

python scripts/run_omy_training.py --dataset "$OMY_DATASET" \
  --work "$OMY_WORK" --stage prepare --checksums "$OMY_CHECKSUMS" --execute

출력은 train 1,926개, validation 478개, tiny-train 최대 48개다. 현재 perturbation 설정에서 카메라 뒤쪽 hypothesis는 건너뛰므로 실제 수는 이보다 작을 수 있다. 이 단계는 학습이 아니라 rendering과 frozen feature 추출이다.

7 처음 하는 작은 학습

python scripts/run_omy_training.py --dataset "$OMY_DATASET" \
  --work "$OMY_WORK" --stage tiny --execute

48개 이하 sample, batch 4, 20 epochs. visual encoder와 pose heads를 고정하고 robot encoder와 fusion만 학습한다. run-tiny-geometry/metrics.jsonl의 train error가 감소하는지 확인한다. 줄지 않으면 전체 학습으로 확대하지 않는다. validation 개선은 이 overfit 진단의 필수 조건이 아니다.

tail -n 5 "$OMY_WORK/run-tiny-geometry/metrics.jsonl"

8 같은 조건으로 비교 학습

python scripts/run_omy_training.py --dataset "$OMY_DATASET" \
  --work "$OMY_WORK" --stage pilot --execute

visual-only와 geometry를 순차 학습한다. 같은 cache/seed와 heads 학습 일정을 사용한다. 새 encoder/fusion 학습률은 1e-4, heads는 1e-5, 20 epochs다. epoch 출력은 0부터 시작한다. best.pt는 validation surface error가 가장 낮았던 checkpoint, last.pt는 마지막 epoch checkpoint다.

9 그다음 motion 비교

처음 학습이 확인된 뒤에만 진행한다. 이전 GT pose를 현재 카메라 좌표로 변환하고 perturbation을 더한 hypothesis를 사용하는 teacher-forced 학습이다.

python scripts/run_omy_training.py --dataset "$OMY_DATASET" \
  --work "$OMY_WORK" --stage motion-prepare --checksums "$OMY_CHECKSUMS" --execute
python scripts/run_omy_training.py --dataset "$OMY_DATASET" \
  --work "$OMY_WORK" --stage motion --execute

동일 temporal cache에서 geometry와 motion을 비교한다. 이 단계는 실제 tracker prediction을 사용한 on-policy 학습이 아니다. tracking rollout으로 별도 검증해야 한다.

10 중단과 재개

각 epoch 끝에 저장한다. 실행 중 Ctrl+C로 중단하면 현재 epoch 중간 상태는 저장되지 않을 수 있다. 같은 cache/mode/batch/warmup 설정을 유지하고 새 output 폴더에서 재개한다. 아래는 geometry pilot을 총 40 epochs로 연장하는 예시다.

python scripts/train_robot_refiner.py \
  --train "$OMY_WORK/train" --val "$OMY_WORK/validation" \
  --mode geometry --batch-size 4 --warmup-epochs 0 --epochs 40 \
  --resume "$OMY_WORK/run-pilot-geometry/last.pt" \
  --output "$OMY_WORK/run-pilot-geometry-resumed"

같은 orchestrator 명령을 다시 실행하면 기존 output 보호 때문에 실패할 수 있다. 실패한 단계만 출력된 개별 명령으로 새 output에 실행하거나 새 OMY_WORK로 처음부터 실행한다. 기존 cache/run을 지우는 방식으로 해결하지 않는다.

자세한 학습 원리와 파일별 설명은 docs/OMY_TRAINING_GUIDE.html을 브라우저에서 연다. HTML은 인터넷 없이 읽을 수 있으며 외부 자료 링크만 네트워크를 사용한다.

Train loss는 epoch 동안 weight가 계속 바뀌며 계산한 평균이고, validation은 epoch 끝 모델로 계산한다. train/eval 모드의 dropout 차이도 있으므로 두 숫자의 대소만으로 오류라고 판단하지 않는다.

metrics.jsonl의 peak_cuda_bytes는 PyTorch의 peak allocated memory이지 nvidia-smi 전체 점유량이 아니다. 시간은 epoch의 학습+validation 중심이며 cache 생성·환경 설치 시간은 별도다.

13 · 학습 완료 후 무엇을 증명해야 하는가

먼저 pretrained visual control, same-data visual-only, geometry, geometry+motion을 같은 초기화·mask·split 조건에서 비교한다. Geometry와 motion 비교는 같은 temporal cache에서 해야 hypothesis 차이를 robot motion 효과로 혼동하지 않는다.

  • A/B/C, 가시성 구간별 error와 실패율을 따로 본다.
  • 정확한 state와 시간 지연/교란 state를 비교해 robot 정보를 실제로 쓰는지 본다.
  • 새 branch에는 CAD점도 추가되므로 robot 정보만의 효과를 더 분리하려면 object-CAD-only 대조군을 추가한다.
  • 안정적인 grasp에는 간단한 gripper-motion propagation도 강한 baseline일 수 있다.
  • C의 부분 가림 초기화는 별도 병목이다. 동일 GT 초기화 진단과 실제 initialization 평가를 구분한다.

현재 evaluate_robot_tracker는 동일 RenderBridge의 sequence runner다. upstream track_one의 모든 전처리와 완전 동일하다는 보장은 아니다. 자체 초기화·실패 감지·재초기화 모듈도 아직 없다.

우리의 contribution 후보는 “encoder 두 개를 합쳤다”가 아니라, 조작 중 robot geometry·motion이 visual tracking을 보완하는 조건을 분리해 보이는 것이다. 기존 V-HOP 등 관련 연구가 있으므로 구조 자체의 최초성이나 효과를 아직 주장하지 않는다.

14 · 막혔을 때 읽을 부분

증상확인할 것
torch.cuda.is_available()가 False활성 Python, driver, 컨테이너 GPU 접근, torch CUDA build. CPU 환경에서 실제 rendering은 불가.
no kernel image / native extension 오류5080 Blackwell 지원 build인지, mycpp/nvdiffrast 등 확장을 현재 torch/CUDA에 맞춰 빌드했는지.
weights 경로 없음 / config 오류submodule 내부 upstream weights 폴더 구조. 캐시만 있으면 rendering까지 가능한 것은 아니다.
새 PyTorch의 torch.load 오류원본 loader와 설치 PyTorch의 serialization 기본값 차이 가능. 출처 확인 없이 임의 checkpoint에 안전 옵션을 해제하지 말고 실제 traceback으로 진단.
Checksum mismatch / missing file공식 최종 dataset인지, 디렉터리명이 dataset인지, 전송이 완전한지. 교체 전 C clip을 섞지 않기.
Output already exists기존 결과 보호다. 새 work/output 경로 또는 완료되지 않은 개별 단계만 사용.
CUDA out of memory다른 GPU 프로세스와 batch 확인. 개별 train 명령에서 batch 2/1로 시작하고 비교 조건도 동일하게 유지.
NaN / non-finite lossdepth 단위, transform, diameter, sample 대응, learning rate 확인. 오류를 무시하고 더 돌리지 않기.
Resume provenance mismatch같은 cache·mode·weights/config인지 확인. cache를 바꾼 재개는 지원하지 않음.

처음은 단일 GPU FP32로 진행한다. AMP/BF16, 다중 GPU, 추가 custom CUDA 최적화는 correctness가 확인된 뒤 검토한다. 특히 renderer와 pose geometry를 무조건 낮은 정밀도로 바꾸지 않는다.

15 · 이해했는지 스스로 확인하기

Q1. Tiny에서 pose heads를 고정하면 gradient도 끊길까?

아니다. weight 업데이트만 막는다. heads 연산을 통해 입력 특징으로 gradient가 전달된다.

Q2. 20 epochs면 새로운 hypothesis를 20번 만들까?

아니다. 현재 fixed cache는 같은 hypothesis를 재사용한다. 새 perturbation에는 새 cache가 필요하다.

Q3. Robot 속도만 추가하면 temporal training인가?

충분하지 않다. 이전 pose를 고쳐 현재 pose로 만드는 학습 예제가 있어야 motion과 correction의 관계를 배울 수 있다.

Q4. Train loss 0.003이면 translation 오차 3mm인가?

그렇지 않다. CAD surface 평균 거리 3mm이며 위치와 회전 오차가 함께 반영된다.

Q5. 9개 validation에서 가장 좋은 모델이면 최종 test 성능인가?

아니다. 그 데이터로 모델을 선택했으므로 독립 test가 아니다.

Q6. 5080에서 Isaac Sim이 실행되면 학습 환경도 준비된 걸까?

아니다. FoundationPose의 PyTorch·CUDA·native extension·weights와 실제 rendering gate를 확인해야 한다.
